# 貿易書類処理 / 01_overview

    ## ビジョン
    国際取引を、紙の運搬ではなく、信頼できるデータ連鎖で動かす。

    ## このドメインをどう見るか
    この領域の本質は、**書類やフォームを処理すること**ではない。  
    本質は、**意思決定に必要な正当性・証拠・ルール適合性・責任所在を、期限内に接続すること**である。

    したがって本テーマは、単なる自動化ツールではなく、次の問いに答える業務基盤として捉える。

    - いま何の案件が動いているか
    - その案件はどの規則・契約・証拠に拘束されるか
    - 次に誰が何をすべきか
    - 何が例外で、何が通常か
    - 顧客価値は「処理件数」ではなく、どの結果改善で測るべきか

    ## 対象ドメイン
    輸出入・通関・運送・金融・保険が紙文書やPDFを前提に連動しており、同じ情報の再入力、到着待ち、整合確認、差し戻しが取引速度と資金化を遅らせている。

    ## 顧客と受益者
    - **一次顧客（予算保持者）**: 荷主、フォワーダー、通関業者、商社、銀行、トレードファイナンス事業者、BPO、輸出入プラットフォーム
    - **現場受益者**: 業務担当者、管理者、監査/統制担当
    - **最終受益者**: エンドユーザー、患者、取引先、契約者、発注者など、処理遅延や品質ばらつきの影響を受ける当事者

    ## 顧客が利益を被るメカニズム
    書類到着待ち削減、再入力削減、船積み遅延抑制、通関エラー低減、資金化前倒し、監査追跡性向上

    重要なのは、「1人の作業を軽くする」だけで終わらないことだ。  
    このドメインでは、遅延や不整合が **売上、資金化、顧客体験、規制対応、監査対応** に波及する。  
    だからこそ、プロダクトの価値は UI の便利さではなく、**業務のボトルネックを外せるか** で決まる。

    ## なぜ10億円級が狙えるか
    ICC Academy は世界で毎日40億件の貿易関連文書が流通し、単一の輸送でも最大50枚の紙が最大30の関係者の間を流れると説明している。APEC は同一情報の最大75%が再入力され、遅延や不一致がサプライチェーン全体を止めうると整理している。[R1][R2]

    ## 主要アクター
    - **輸出者**: 船積み条件・請求条件の起点を作る
- **輸入者**: 書類受領・商品引取・支払の責任を持つ
- **フォワーダー**: 輸送手配と書類流通を調整する
- **通関業者**: 各国税関へ申告する
- **銀行**: LC・貿易金融・書類審査を行う
- **保険者**: 貨物保険や事故時証憑を扱う

    ## 提供するべきプロダクトの姿
    この領域では、チャットUIや文書要約だけでは不十分である。必要なのは以下を備えた「業務OS」である。

    1. 案件・ケースの集約
    2. ルールと証拠の接続
    3. 例外の検知と優先順位付け
    4. 関係者へのアサインと追跡
    5. 監査証跡と再現性
    6. 学習ループ（過去案件を次回運用へ還元）

    ## 本資料におけるプロダクト方針
    - ドメイン用語を先に定義し、実装詳細は後ろに置く
    - 生成AIは一部機能であり、中心はケース運用と状態管理
    - 既存基幹システムを置き換えるより、**既存システム間の高摩擦部分を支配する**
