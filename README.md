# TradeDocFlow

貿易書類案件管理システム — 輸出入に必要な書類の収集・審査・判断を、チームで追跡・管理するための業務ツール。

---

## Why（なぜ必要か）

国際貿易では、1件の取引に最大50枚の書類が最大30の関係者間を行き来する（ICC Academy 調査）。現場では ERP などの基幹システムが存在していても、**書類の不足・差し戻し・例外処理**という「詰まり」の部分は依然として担当者が個別に管理しており、案件ごとにメール・スプレッドシート・紙ベースで追いかけているのが実態だ。

TradeDocFlow は、この「高価な例外処理」を業務の中心に据え、誰が何を持っていて、何が足りなくて、次に何をすべきかを一目で把握できる **ケース中心の業務プラットフォーム** を提供する。

---

## Problem（課題）

| 課題 | 現場の痛み |
|------|-----------|
| 書類の追いかけ | メール・電話・スプレッドシートで担当者が個別管理 |
| 例外の属人化 | 差戻し・不一致・追加資料要求が担当者の記憶に依存 |
| 判断根拠の不透明 | 承認・否決の理由が後から追えない |
| SLA 超過の見逃し | 期限を過ぎてから気づく |
| 監査対応のコスト | 誰がいつ何を判断したかを後追いで再現できない |

---

## Solution（解決方法）

TradeDocFlow は以下の仕組みでこれらの課題を解決する。

1. **Case（案件）中心の追跡**  
   すべての輸出入取引を「ケース」として管理。状態（Draft → 審査中 → 承認/却下）を明示的に遷移させる。

2. **必要書類の自動算出と完成度スコア**  
   案件種別（輸出/輸入）に応じて必要書類リストを自動生成。証憑が提出されるたびに完成度スコアをリアルタイム更新。

3. **判断支援パネル（Decision Support）**  
   書類の過不足を解析し「承認推奨 / 却下推奨 / 例外エスカレーション」を担当者に提示。判断は人間が確定するが、**材料の準備は機械が行う**。

4. **例外の明示的管理**  
   差異・不一致が発生した案件を「例外処理」ステータスに昇格し、通常フローとは分けて追跡する。

5. **監査証跡（Audit Trail）**  
   すべての状態変更・証憑提出・判断確定をタイムラインに記録。後から誰がいつ何をしたかを再現できる。

## How to use（使い方）

### セットアップ

```bash
# リポジトリのクローン後、依存パッケージをインストール
npm install

# 開発サーバーを起動
npm run dev
```

ブラウザで [http://localhost:3000](http://localhost:3000) を開く。  
初回アクセス時にデモデータが自動投入される。

### プロダクションビルド

```bash
npm run build
npm start
```

### 基本操作フロー

```
1. ダッシュボード       → 案件の全体像・統計・最近の案件を確認
2. 案件一覧            → ステータスでフィルタして対応が必要な案件を特定
3. + 新規案件起票      → 案件タイトル・種別・担当者・期限を入力して起票
4. 案件詳細            → 必要書類の確認、証憑の登録、判断の確定
```

#### 証憑の登録

案件詳細の「必要書類・証憑」パネルで、未提出の書類に「証憑を追加」ボタンが表示される。書類種別・ファイル名・提出者・有効期限を入力して登録すると、完成度スコアが更新される。

#### 判断の確定

すべての書類が揃うと「判断支援」パネルに「承認推奨」が表示される。「判断を確定する」ボタンから承認・却下・例外エスカレーションを選択して確定する。確定内容は監査証跡に記録される。

## アーキテクチャ

```
src/
├── app/
│   ├── page.tsx              # ダッシュボード
│   ├── cases/
│   │   ├── page.tsx          # 案件一覧
│   │   ├── new/page.tsx      # 新規案件起票
│   │   └── [id]/page.tsx     # 案件詳細
│   └── api/
│       ├── cases/route.ts            # GET 一覧 / POST 作成
│       ├── cases/[id]/route.ts       # GET 詳細 / PATCH ステータス更新
│       ├── cases/[id]/evidence/      # POST 証憑追加
│       ├── cases/[id]/decision/      # POST 判断確定
│       └── seed/route.ts             # POST デモデータ投入
├── lib/
│   ├── db.ts                 # SQLite 初期化・クエリ
│   └── seed.ts               # デモデータ定義
├── components/
│   ├── Navigation.tsx
│   ├── StatusBadge.tsx
│   ├── CaseCard.tsx
│   └── EvidenceCompleteness.tsx
└── types/index.ts
```

## ドメインモデル（主要概念）

| 概念 | 説明 |
|------|------|
| **Case** | 1件の輸出入取引案件 |
| **Requirement** | 案件成立に必要な書類・審査 |
| **Evidence** | Requirement を満たすために提出された資料 |
| **Decision** | ルールと証拠に基づく判断（承認/却下/例外） |
| **Audit Trail** | すべての操作の後追い可能な操作履歴 |

**案件ステータス遷移**

```
Draft → IntakeValidated → WaitingForEvidence → InReview → Approved
                                                         → Rejected
                                                         → Exception → WaitingForEvidence
```
